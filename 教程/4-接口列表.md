> 分析日期：2026-10-02。源码基线：`df32bf6e50a40843438f9491a26069ca4bd08f1f`。以当前代码实际注册关系为准，不只照抄 `docs/zh/api/`。接口与测试匹配明细见 [7-测试用例.md](7-测试用例.md)。

## 1. 范围、URL 和计数口径

主入口是 `openviking/server/app.py:create_app`。该入口无条件挂载 26 个 router，其中 25 个提供 REST/健康/指标/代理，1 个提供 WebDAV；OAuth router 是额外的条件挂载。路由文件中的路径需要拼上 `APIRouter(prefix=...)`，再拼上 `app.include_router(..., prefix=...)`；例如 Bot router 自身没有前缀，主服务挂载后是 `/bot/v1/chat`。Bot Studio 使用常量 `ACCOUNT_BOT = "/accounts/{account_id}/bot"`，不能只搜索装饰器里的引号字符串。清点脚本通过 Python AST 求值常量、字符串相加及注册前缀，并展开 favicon 字典循环、MCP Starlette Route、条件 OAuth 挂载。

主服务的默认基址是 `http://127.0.0.1:1933`。以下主服务表给出完整默认 URL 模板；部署时替换协议、主机、端口或代理基路径。`{session_id}` 等是必填路径参数，`:path` 是 Starlette 多段路径转换器；实际 URL 不携带 `:path`。查询参数不属于路由标识，具体请求/响应模型可从每行的处理函数与 [openviking/server/models.py](../openviking/server/models.py) 继续查看。

| 主服务类别 | 方法 × 路径组合数 | 挂载条件/口径 |
| --- | ---: | --- |
| 25 个 REST router 的业务、健康、指标、Bot 代理 | 165 | 无条件注册；功能仍可能因组件配置不可用 |
| WebDAV | 16 | 同一主服务，独立协议，不算入 REST 分母 |
| OAuth 自有路由 | 5 | `oauth.enabled`，且注册过程成功 |
| OAuth SDK 路由 | 12 | 10 个显式方法组合，另有 2 个隐式 HEAD；同上 |
| MCP 传输 | 4 | 显式 GET/POST/DELETE，另有隐式 HEAD；工具数量另计 |
| Studio 页面与 favicon | 9 | 3 个 Studio 路由需存在可用前端 bundle；6 个图标始终注册 |
| FastAPI 自动文档 | 8 | 4 个 GET 与 4 个隐式 HEAD |
| **主服务配置并集** | **219** | 含可选挂载、框架方法；不等于一次默认启动全都可用 |

方法数按注册的 `(HTTP method, path template)` 计，不将路径参数的每个值算新接口，也不把 CORS 中间件接受的预检展开为每条业务路由的额外 OPTIONS。GET FastAPI `APIRoute` 不由此假定都有 HEAD；本表只对 Starlette `Route` 类型的 MCP、SDK 和默认文档补计隐式 HEAD。依据是锁定的 [Starlette 0.52.1 Route 实现](https://github.com/encode/starlette/blob/0.52.1/starlette/routing.py#L225)。注册某方法不保证该方法请求能成功，例如 MCP 传输可拒绝不支持的请求。

## 2. 主服务协议和鉴权边界

REST 主要是 JSON 请求/响应。业务结果通常使用 `status/result/error` 信封，通用异常经 `server/error_mapping.py` 与 `server/models.py` 转为 HTTP 状态和错误码；下载、快照 blob、Prometheus、SSE、WebDAV、OAuth 页面并非该 JSON 信封。`POST /api/v1/resources/temp_upload` 是 multipart 上传入口，返回临时上传令牌；后续资源或包导入用令牌接续，不能把它当作永久公开文件下载地址。

鉴权模式由 `ServerConfig.get_effective_auth_mode()` 与 `server/auth/` 插件决定：`api_key` 接受 `X-API-Key` 或 `Authorization: Bearer <key>`（[openviking/server/auth/__init__.py](../openviking/server/auth/__init__.py)，第 42 行 优先取 X-API-Key），`trusted` 校验受信上游身份，`dev` 用于开发身份。账户/用户/组与 URI ACL 再约束可访问范围。`/health`、`/ready` 是无鉴权探针；其余接口是否需要 ROOT、ADMIN 或普通身份，应以每个 handler 上的依赖/鉴权装饰器为准，例如账户创建、删除和迁移使用 `require_auth_root`。`/metrics` 不使用账户业务权限，其暴露边界由部署控制。

Bot 主服务路由始终 include；`with_bot` 仅决定是否初始化 Bot 代理目标与凭证，未启用时调用代理可返回不可用错误。Bot Studio 也始终 include，但 `include_in_schema=False`，因此仅看 OpenAPI 会漏掉它。主服务这组接口与独立 Gateway 的接口并不完全相同。

### 8.8 WhatsApp Node Bridge 与部署等待服务

[bot/bridge/src/server.ts](../bot/bridge/src/server.ts)，第 29 行 创建 WebSocket server，绑定 `127.0.0.1` 与配置端口，地址为 `ws://127.0.0.1:{bridge_port}`（不限制额外路由路径）。可选 token 时第一条消息必须是 `{"type":"auth","token":"..."}`；Python 发送 `type=send`，服务返回 sent/error，并广播 message/status/qr。这不是 REST API，也不共用主服务 `/mcp`。

[deploy/docker/pending_health_server.py](../deploy/docker/pending_health_server.py) 只在部署缺配置等待期间临时占用默认 1933 端口；GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS 对任意 URL 路径均返回 `503 pending_initialization`（HEAD 无正文）。它是配置故障时的替代响应，真实主 server 正常启动后由其接管端口，不是一套永久业务接口。

Rust RAGFS、PyO3 文件系统绑定及 C++ index engine 的函数/ABI 不属于 HTTP URL。外部供应商、S3、模型和消息渠道的 API 也不是本仓库后端“暴露接口”；可结合 [1-模块关系.md](1-模块关系.md) 了解被调用方向。

## 9. 废弃接口、可复算清单和校核限制

代码显式标记 deprecated 的五个方法/路径组合是：GET/PUT `/api/v1/admin/agent-evolution`，GET/PATCH `/api/v1/admin/accounts/{account_id}/settings`，以及 POST `/api/v1/search/recall`。这些仍注册并保留兼容行为；运行时配置应优先看账户 configuration 路由，recall 迁移至 search 的 `mode=context`。未标 deprecated 的其他路由不能仅因名字较旧就宣布废弃。

使用 [辅助脚本/清点接口与测试.py](辅助脚本/清点接口与测试.py) 可重新生成完整 route 清单，脚本不导入项目、不启动服务，不需要模型配置：

```sh
python3 教程/辅助脚本/清点接口与测试.py --output /tmp/openviking-audit
```

生成的 `api-inventory.json` 包含每条路由的 scope、method、完整 path、source、line、handler、deprecated 和注册方式；`mcp_tools` 包含实际工具名与源码。清点结果可以通过上述脚本重新生成，无需依赖临时目录长期保存。第一方 AST 路由均可求值，未发生无法解析的 prefix/path；SDK 五组动态 OAuth 路由按锁定源码人工核对后作为明确外部项加入，升级 MCP 版本会令脚本报错要求重新核对。框架隐式 HEAD 独立标注，不声称是第一方装饰器。

这是静态注册关系审查，没有启动所有应用或执行外部供应商请求。是否可用取决于配置、组件初始化、权限、资源存在与条件挂载；可选配置并集的 219 不宜当作任何一台运行实例的 OpenAPI endpoint 数。
